## Git Conventions

### Branch Naming
- Feature branches: `feature/<short-description>`
- Bug fixes: `fix/<short-description>`
- Documentation: `docs/<short-description>`
- AI/Claude work: `claude/<short-description>` (auto-generated by Claude Code)

### Development Branch
All active development is done on feature branches — never directly on `main`. The current working branch is `claude/add-claude-documentation-MR1Wp`.

### Commit Messages
- Use the imperative mood: "Add feature" not "Added feature"
- Keep the subject line under 72 characters
- Reference issues/PRs where relevant: `Fix login timeout (#42)`

### Pushing
Always push with tracking:
```bash
git push -u origin <branch-name>
```

## Working in This Repository

### Before Making Changes
1. Read the relevant files before editing — never modify code you haven't read
2. Run existing tests to establish a baseline
3. Understand the existing patterns before introducing new ones

### Making Changes
- Prefer editing existing files over creating new ones
- Match the style and conventions of surrounding code
- Do not add features, refactoring, or cleanup beyond what was asked
- Do not add docstrings/comments to code you didn't change
- Do not add error handling for scenarios that cannot happen

### After Making Changes
- Verify the change works as intended
- Commit with a clear, descriptive message
- Push to the feature branch (never to `main`)

## AI Assistant Behavior Guidelines

### Do
- Read files before editing them
- Confirm before taking destructive or irreversible actions (force push, file deletion, dropping DB tables)
- Keep changes minimal and scoped to the request
- Ask for clarification when a request is genuinely ambiguous

### Do Not
- Push to `main` without explicit user approval
- Create pull requests unless explicitly asked
- Add speculative features or "nice to haves"
- Skip git hooks (`--no-verify`)
- Amend commits that have already been pushed

### Risky Actions Requiring Confirmation
- `git reset --hard`, `git push --force`
- Deleting files or branches
- Any change to CI/CD pipeline configuration
- Modifying shared infrastructure or environment secrets
